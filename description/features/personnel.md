# 人员管理

人员管理接入正式用户、部门与平台接口，提供用户名、部门及管理员联合筛选和用户卡片，不保留临时 mock 数据。提供组织架构同步操作，同时支持员工平台访问等级及管理员身份更新。

## 布局与交互

顶部依次为用户名、部门及平台管理员筛选，右侧提供“刷新组织架构”按钮，复用数据中心重置按钮的立体灰色模板；首次点击向上滚入橙色“确认刷新”，3 秒内再次点击才调用 `POST /user/refresh-all`，420ms 入场期间使用原生 disabled 禁用按钮，拦截连点；超时向下滚回，不提供取消按钮。确认后继续向上滚入“刷新中”，持续使用原生 disabled 禁用按钮，禁用态不产生按压反馈，列表刷新及重试入口同时锁定且处理函数再次校验，切换工作台不取消请求也不重复提交；后端成功后重新读取人员、部门及平台管理员资料，保留有效筛选条件。失败显示后端信息及数据库是否已更新，不自动重试，重新操作仍需二次确认。成员列表的圆形刷新按钮仅执行 GET 查询，不调用组织架构同步。窄屏下按钮换行靠右。下方卡片展示头像、用户名和所属部门，盾牌表示平台管理员。桌面三列、中等窗口两列、窄屏单列，筛选保留淡入淡出及补位过渡。部门及平台管理员使用统一的轻量下拉面板，包含浅绿选中态、勾选标识、滚动区域和展开收起过渡；支持方向键、Home／End、回车确认、Escape 关闭、Tab 离开和点击外部关闭，切换工作台后自动收起。

用户名、部门与管理员条件取交集。输入用户名时，在当前部门及管理员范围内提供候选，失焦或回车后应用姓名／用户 ID 的文本包含匹配；选择候选时按 userid 精确筛选，同名用户不会混淆。只剩一位匹配人员时滚动并高亮该卡片。选择人员不会重置其他条件；条件冲突时显示空结果，“清空筛选”同时清除三个条件。

部门筛选沿用单选，按 `department_ids` 数组包含所选 ID 匹配，员工任一归属与所选部门一致即可命中，与用户名及管理员条件取交集；每名员工按唯一 userid 只展示和计数一次，不按部门拆成多条。部门选项保留没有员工的部门，缺少名称的归属以“部门 #ID”补入选项。卡片、候选提示和权限弹窗使用相同的全部部门名称，按接口顺序以顿号分隔，不标记主部门。管理员下拉首项为“不启用”，后续仅展示 `is_management_entry=true` 的平台名称（符合标记的注册中心及离线平台也可展示）。不启用时不限制管理员身份；选择具体平台后，仅显示该平台的管理员，与用户名、部门条件取交集。平台成功刷新后若已选平台被移除或不再是管理入口，则恢复“不启用”。首次平台目录失败时，管理员身份保持未知，禁用管理员筛选；已有成功目录时保留最近结果并提示更新失败。人员或部门刷新失败保留上一次完整快照，提供重试入口。人员和部门目录由 `WorkspaceLayout.vue` 持有并提供共享实例，进入任一工作台时首次完整加载，成功后在当前应用内缓存，包括空数组；人员管理和数据中心／文件等级调整的审核人姓名映射复用同一快照，不按文件逐个查询人员。工作台切换及恢复页面可见时复用数据，不重复请求；人员筛选仍由本页独立保存。首次失败或中断时可重新进入重试；“刷新人员列表”及错误重试主动查询最新完整快照。组织架构刷新成功后使人员缓存失效并重新读取；即使此时已切换到其他工作台，仍更新共享快照；页面隐藏时待恢复可见后读取。页面刷新、工作台外框卸载或共享凭据改变后重新加载，不复用旧身份快照。

## 接口与模型

接口均使用共享用户 Bearer token；查询不附加筛选参数，组织架构刷新不发送参数或请求体。开发路径增加 `/dev`，由网关与 Vite 原样转发。契约见后端[用户与部门 API](../../../registry-be/description/api/user.md)、[平台 API](../../../registry-be/description/api/platform.md)。

| 接口后缀 | 用途 |
| --- | --- |
| `POST /user/update-permissions` | 增量更新员工平台等级及管理员关系，并等待中间件同步 |
| `POST /user/refresh-all` | 从钉钉刷新已有员工姓名、部门，增量同步姓名；不会导入全量新员工 |
| `/user/user-list` | 读取 userid、name、department_ids、avatar_url、platform_permissions，兼容旧 department_id |
| `/user/department-list` | 读取部门 id 与 name |
| `/platform/list` | 读取完整平台目录及 admins，包括 registry 和离线平台 |

生产前缀为 `/knowledge-accumulation/registry/api`，开发前缀为 `/dev/knowledge-accumulation/registry/api`。用户接口的 `name` 映射为展示名，空值回退 userid；账户栏仍使用 `/auth/me` 的 `username`。部门找不到时显示“部门 #ID”。部门 ID 和权限整数按十进制字符串保存，避免大整数精度损失。`department_ids` 为完整归属，去重后保存在 `departmentIds`；仅旧响应缺少此字段时回退 `department_id`，数组存在但为空或非法时报告加载失败，不用旧字段掩盖异常。旧兼容值不参与新数组的主次判断，也不追加进数组。

模型位于 [personnel.js](../../src/models/personnel.js)。按大小写敏感的 userid 关联 `admins[].userid`，不按同名或权限值判断。权限值 0 保留，缺少权限与 0 不等同；管理员身份与平台权限独立。`platformAccess` 合并完整目录及用户权限中的平台，保存名称、在线状态、是否授权、权限值、管理员身份及子管理平台／管理入口标记。共享目录的 `allPlatforms` 用于人员建模，数据中心文件夹使用排除 registry 且标记为子管理平台的 `subManagementPlatforms`。

刷新接口同步等待后端完成，前端时限 330 秒（后端默认 300 秒），部署网关读取超时同步设为 330 秒。请求失败不等于数据库未变更；网络中断或超时会提示结果未确认，不自动重发，支持先通过成员列表 GET 查询核实。

## 员工权限弹窗

点击成员卡片或用键盘激活后，打开该员工的权限弹窗。按平台逐行展示名称、代号及访问等级；平台图标复用知识沉淀统一入口的注册中心和合同平台 WebP，在 `platformAppearance.js` 中按平台代号映射，其他平台保留通用图标。仅为子管理平台展示 0–100 等级滑块、数值输入及等级校验；仅为管理入口展示右侧管理员复选框；两个条件独立，隐藏等级不参与校验，保留列标题，不额外重复“管理员”文字；复选框保留包含平台名称的无障碍标签。等级和管理权互不推导；空数值表示未授权，与明确的等级 0 区分。原始异常等级不会静默截断，显示校验提示。

“更新”在草稿有有效修改时可点击：首次向上滚入橙色“确认更新”，420ms 入场期间原生禁用，3 秒内再次点击才提交；超时向下返回。修改等级或管理员勾选、切换员工、关闭弹窗均清除确认状态。只提交相对打开弹窗时发生变化的可见字段：空等级转为 null 撤销，0 保持有效整数；未修改或隐藏的平台字段不发送。管理员资料未知时禁用相应选择与更新。

提交使用 `POST /user/update-permissions`，前端时限 60 秒，覆盖后端默认 40 秒执行时限。期间禁用编辑、关闭及重复提交，锁定人员列表和组织架构刷新；切换工作台关闭弹窗但不取消更新。成功响应通过基本契约校验后关闭弹窗；人员管理仍为当前工作台时，在视口顶部居中显示带员工姓名的绿色成功 toast，3 秒后自动淡出，不占用列表布局、不抢占焦点，支持屏幕阅读器与减少动画偏好。重新编辑或离开人员管理时清除提示，切走期间完成的更新不在其他工作台弹出。成功后使人员缓存失效并重新读取人员及平台管理员资料；刷新失败保留旧快照并显示现有重试入口，不将保存成功误报为保存失败。更新后的人员快照同时用于数据中心的审核人姓名展示；页面隐藏时在恢复可见后重新读取。

提交失败保留原始草稿，显示后端信息及数据库提交状态，不自动重发。数据库已更新但同步未完成时，可再次二次确认提交相同变更以重试同步。网络失败、超时、无效成功响应或服务错误会提示结果可能已生效，并重新查询列表；后台查询不覆盖当前草稿。409 冲突会重新查询并禁用本次草稿提交，须关闭后重新打开编辑。撤销自身 registry 管理权后，后续查询可能返回 403，沿用统一的无权限返回入口。关闭后未保存草稿丢弃，再次打开使用当前列表快照。

弹窗沿用浅色圆角表面与模糊遮罩，内容独立滚动，支持关闭按钮、Escape 及点击遮罩关闭，关闭时恢复卡片焦点；切换工作台关闭弹窗。窄屏保持等级控件在左、管理员复选框在右。

## 头像读取与释放

用户的 `avatar_url` 为文件名，前端保存为 `avatarFilename`，仅接受 32 位小写十六进制加 `.webp`，不接受外部 URL 或目录。通过 `GET /knowledge-accumulation/registry/api/resource/avatar/{filename}` 携带共享 Bearer 读取 WebP，开发请求自动增加 `/dev`，不直接请求知识后端。

图片完成解码后淡入，缺少头像、404、服务异常或解码失败时显示姓名首字。401／403 沿用统一鉴权回退。头像请求使用浏览器默认 HTTP 缓存，遵循成功响应的 `Cache-Control: private, max-age=86400` 和 `Vary: Authorization`，缓存时长由后端配置决定（默认一天，设为 0 时不缓存），凭据变化时独立获取；头像更新后文件名变化，新地址立即加载新图片。错误响应为 `no-store`，失败可重试。前端仍合并同一凭据、同一文件的并发请求，不额外建立 localStorage 或页面 Blob 缓存；目录、身份及文件原件请求仍保持原缓存策略。展示使用临时 Blob URL，文件名变化或卡片卸载时释放；迟到结果不会覆盖已卸载的卡片，凭据变更后的旧响应不会显示。

成员列表读取及刷新使用居中转圈；空列表及筛选无匹配淡入 `empty.webp` 和“空空如也”，筛选为空时保留“清空筛选”入口。统一规则见[列表与详情的状态展示](workspace.md#列表与详情的状态展示)。

## 验证

此前隔离联调复用正式 FastAPI 用户、部门、平台、身份和头像路由，替换数据依赖，不读取真实数据库；覆盖同名用户、registry／离线平台管理员、大整数部门 ID、无员工部门、刷新失败保留、平台失败与重试、空列表、头像鉴权与窄屏布局。头像缓存联调验证同一凭据重复读取不产生新网络请求、新文件名独立加载、不同凭据隔离及 401 不缓存。组织架构刷新通过正式路由的隔离服务验证 GET／POST 分离、首次点击不提交、入场连点拦截、超时回退、等待期间锁定、工作台切换防重发、成功重查及部分失败提示。历史自动测试还覆盖头像并发合并、失败重试及凭据变化；当前可运行范围见根目录 [README](../../README.md#构建预览与验证)。当前权限测试覆盖仅提交修改的可见字段、等级 0 与撤销区分、未知管理员保护、Bearer 请求、无效回执及 409／422／503／401／403 等失败路径。多部门回归覆盖数组优先、单值兼容、重复部门、大整数 ID、未知部门、同名人员精确选择、组合筛选和单人单次计数；此前浏览器验证下拉选中态、键盘选择、清空及刷新后的选项变化。

## 平台能力与权限控件

平台目录的三个布尔标记随接口同步建模，完整平台与用户权限仍保留在内存模型中，标记仅控制界面展示，不作为用户权限判定。

- 员工权限弹窗只为 `is_sub_management_platform=true` 的平台展示等级滑块、数值输入及校验。
- 仅为 `is_management_entry=true` 的平台展示管理员选择框；顶部平台管理员筛选也仅列出这些管理入口。
- 两个标记独立：同时满足则同时展示两项控件；都不满足或权限代号未出现在目录中则不展示该行。不能用 `is_alive` 或 `supports_a2a` 代替这两个条件，离线平台仍遵循同一规则。

更新仅提交已修改的可见控件，不将隐藏的控件理解为撤销已有等级或管理员身份。
