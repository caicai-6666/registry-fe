# 我的审核记录

右上角原信箱入口改为“审核记录”，沿用原图标。弹窗参照 `contract-service-fe` 的 `ReviewLogDialog.vue`：浅绿渐变顶部、圆角大弹窗、背景模糊、左侧记录列表及右侧详情；窄屏改为上方列表、下方详情，各自滚动。顶部提供“入库审核／删除审核”切换、当前类型记录刷新和关闭按钮，类型及详情切换采用淡入淡出，尊重减少动画偏好。

## 本人入库审核历史

[`reviewHistoryApi.js`](../../src/services/reviewHistoryApi.js) 调用 `GET /registry/api/ingestion-review/history`，使用现有 Bearer 人员会话，不传 `reviewer` 查询参数，由后端按当前登录身份查询。页面没有查看其他人员的入口，前端解析还会按当前账户名称精确过滤。具体契约见[后端入库审核历史](../../../registry-be/description/api/ingestion-review.md#按审核员获取入库审核历史)。

[`reviewHistory.js`](../../src/models/reviewHistory.js) 校验公开展示字段、带时区时间、已完成的 `approved`／`rejected` 状态和 SQLite 审核 ID。ID 精确保留为字符串，拒绝重复及无效响应，保留后端倒序，不将申请人当作审核人。

列表显示文件名称、来源平台名称及通过／拒绝状态，不显示申请时间；申请时间保留在详情的申请信息中。默认选中第一条，详情直接从文件摘要开始，不重复展示顶部文件名、平台及审核状态标签；申请信息对齐排列，通行证使用独立浅绿区域并支持长值换行。历史空人员或未知通行证 null 显示“—”，通行证数组逐项展示，空数组显示“无通行证”，摘要为空显示“暂无摘要”。内容按文本展示，不执行 HTML。此入口只读历史，不提交审核决定，不自动请求原件。

[`useReviewHistory()`](../../src/composables/useReviewHistory.js) 在弹窗打开、返回入库类型或可见性恢复时获取历史；重复进行中的请求合并，关闭、切换删除类型、隐藏或卸载时取消，晚到响应不覆盖新状态。手动刷新可读取最新记录，失败保留上次成功记录并显示错误和重试，成功空数组清空旧记录及详情。401 使用既有会话失效流程。页面内保留最近结果和仍存在的选中记录；重新打开默认回到入库审核并重新查询，刷新和退出清空内存状态。

## 本人关联的删除审核历史

“删除审核”调用 `GET /registry/api/deletion-review/history`，携带 Bearer，不传 `reviewer` 查询参数，由后端按当前登录人员返回关联历史。具体契约见[删除审核历史](../../../registry-be/description/api/deletion-review.md#按审核员获取删除审核历史)。

返回范围包括当前人员作出删除决定的记录，以及当前人员曾批准入库的文件的删除记录。响应中的 `reviewer` 是实际删除审核员，可能不是当前账户；前端不再次按响应姓名过滤，避免丢失原入库审核员关联到的记录。

删除历史没有文件名和摘要字段，也不依赖已删除的正式目录；页面使用“文件资源 #resource_id”标识，未绑定资源时显示“删除申请 #审核ID”。列表显示平台名称及批准／拒绝删除状态，不显示申请时间；详情从“文件摘要”开始，因接口无此字段而显示“暂无摘要”，后续展示申请人、申请时间、删除原因、实际删除审核人、意见、审核时间、资源编号和原通行证。未知字段显示空值提示，不生成名称或摘要，不自动请求原件。资源 ID 支持 unsigned BIGINT 上限，使用 JSON 原始数字文本精确保留。

两个类型各自持有记录、加载／错误状态及选中 ID；类型切换会取消离开的请求并读取新类型，不互相覆盖。两种记录均支持刷新、失败保留与重试及成功空状态，接口错误不会伪装为无记录。此功能只读历史，不提交删除决定。

## 弹窗与验证

[`ReviewHistoryDialog.vue`](../../src/components/ReviewHistoryDialog.vue) 使用原生 dialog 提供模态焦点约束；关闭按钮、Escape 和遮罩外点击可关闭，关闭后焦点返回入口。打开弹窗暂停背景动画，关闭恢复；路由切换、退出或会话失效会收起弹窗。

既有测试及生产构建验证通过，当前总体基线见根目录 [README](../../README.md#构建预览与验证)。使用 `tests/catalog_backend_fixture.py` 的隔离数据与实际 FastAPI 历史路由验证本人历史、通过／拒绝详情、历史空字段、错误后保留和重试、成功空列表、类型切换、关闭及桌面／390px 窄屏显示。测试不访问生产数据库，不提交真实审核。

[桌面审核记录](../assets/screenshots/review-history-desktop.jpg) · [窄屏审核记录](../assets/screenshots/review-history-mobile.jpg)。截图为隔离测试账户及数据。

开发与生产均直接读取真实入库及删除审核历史接口；临时预览记录及开发开关已移除。历史预览截图只用于说明样式，不代表当前账户的真实数据。

来源平台复用共享平台目录及公开模型，优先按 `source_platform` 查找平台名称，目录未加载或缺少平台时回退代号；离线平台同样显示名称。平台目录由注册中心布局统一持有，在数据中心可见或审核记录打开时同步，弹窗与结果列表不另行请求重复目录。

刷新按钮沿用参考项目的单箭头圆弧图标和圆形阴影按钮，刷新期间按 0.8 秒／圈旋转，读取完成后转完当前圈再停，期间禁止重复点击。关闭或切换类型时重置动画，减少动画偏好下不旋转。

删除历史已用实际 FastAPI 路由隔离联调，验证原入库审核员关联返回的其他删除审核员记录、BIGINT、未绑定资源、空字段、类型选择保留、失败重试、空历史及桌面／窄屏显示。[查看删除审核记录](../assets/screenshots/deletion-history-desktop.jpg)。

两种历史的 `passport` 均按字符串数组或 null 解析，统一规则及目录筛选见[通行证数组契约](catalog.md#通行证数组契约)。

详情不显示顶部文件名称、来源平台栏或右上角的审核结果标签，直接从文件摘要开始；列表中的审核状态继续保留，入库及删除审核记录均遵循此布局。
