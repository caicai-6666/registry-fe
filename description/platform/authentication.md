# 登录与后端鉴权

本页说明真实人员登录、浏览器会话和 JSON 请求入口。具体人员密钥与后端免登码策略以[后端登录 API](../../../registry-be/description/api/auth.md)为准；开发和云端地址见[环境与部署](deployment.md)，页面跳转与访问守卫见[页面路由](routing.md)。

## 登录流程

[`src/services/registryApi.js`](../../src/services/registryApi.js) 通过当前环境的同源 API 基础路径下的 `POST /auth/login` 提交 JSON，请求体仅包含 `secret_key`。页面上的“登录密码”对应后端人员密钥，按原始输入发送，不去除首尾空白，也不提交账户名称。

开发 API 使用 `/dev/registry/api`，生产与构建预览使用 `/registry/api`；基础路径按照 Vite 的开发标识选择，具体映射链路见[环境与部署](deployment.md)。

成功响应必须包含非空字符串 `login_code` 和 `user_name`，映射为 `loginCode` 和 `userName`。注册中心右上角使用后端返回的名称。登录进行期间禁止重复提交；请求取消、网络失败、15 秒超时、后端拒绝、格式错误或无效响应均不会进入注册中心。

验证成功后保留原登录卡片及加载状态，在隐藏且禁止交互的工作台内完成首屏准备：默认数据中心等待目录及平台首轮查询，审核广场等待当前申请及关联目录，人员管理只等待布局；同时等待可见工作台图标解码、有限入场动画和渲染帧，再退出登录页。图标等待最多 5 秒，接口沿用现有超时；业务加载失败会进入带错误及重试入口的工作台，401 仍返回登录页，不无限等待成功。筛选及后台平台轮询不重复触发入场等待。

前端已移除固定 `111111` 的 mock 校验。是否接受该密码由后端人员文件决定；本机与生产人员配置各自独立，不能通过修改前端代码创建审核身份。旧 `registry.mock-auth-session.v1` 会话会被清除，不能恢复真实登录。

## 会话与退出

免登码与名称存入当前标签页的 `sessionStorage`，开发键为 `registry-development-reviewer-session.v1`，生产键为 `registry-reviewer-session.v1`，避免同域名下开发与生产混用凭据；原始人员密钥不保存。同一标签页刷新可以恢复会话，存储不可用时使用页面内存。退出时清除本地会话、关闭审核记录弹窗并通过路由返回空密码框的登录页。

后端目前没有会话检查、登出撤销或独立续期接口，前端不会编造这些请求。恢复缓存只表示存在会话凭据，不证明后端仍认可该凭据；受保护接口返回 `401` 时才统一清除会话并提示重新登录。后端重启或免登码到期后，旧凭据可能失效。

## JSON 业务请求

后续业务接口通过 `registryApiRequest('/接口路径', options)` 接入。该入口将路径限制在当前环境的注册中心 API 基础路径下，添加 `Authorization: Bearer <login_code>` 并返回 JSON；不允许完整外部 URL 或离开注册中心接口范围的路径，以免把凭据发给其他平台。

`401` 响应清理当前会话并发出 `registry-auth-expired` 事件，由 [`App.vue`](../../src/App.vue) 通过路由返回登录页并显示失效提示。重新登录后，旧请求的 `401` 不会清除新会话。登录接口不携带旧 Bearer 凭据，也不会把无效密钥提示当作已有会话过期。

JSON 接口使用 `registryApiRequest()`；原件使用 `registryApiFileRequest()`，复用同源路径、Bearer、期限、取消与 401 处理，返回 Blob 和响应头，见[目录与原件接入](../features/catalog.md)。流式消息未接入，原信箱入口现为[本人审核记录](../features/review-history.md)。
