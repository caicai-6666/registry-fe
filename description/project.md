# 知识沉淀注册中心前端：项目开发原则

> **项目定位：** 本仓库是“知识沉淀注册中心”的前端项目，为注册中心后端提供浏览器端页面与交互入口。

本文件记录项目定位、开发边界和整体布局要求。当前已实现背景、真实人员登录、会话鉴权、数据中心左右布局，左侧为平台及条件筛选，右侧为文件列表，平台列表与后端同步计划已接入。

---

## 1. 项目定位与业务背景

知识沉淀注册中心集中接收各子平台的数据入库、数据删除申请，开展审核并反馈结果，由子平台根据反馈处理自身数据。注册中心后端还提供辅助管理的智能体能力，具体能力范围随需求逐步明确。

本项目负责页面呈现、用户交互、前端状态和后端接口接入。申请接收、审核规则、数据持久化、结果反馈及智能体执行由后端负责，前端不直接连接数据库、消息中间件或模型服务。

后端职责和业务流程见[后端项目说明](../../registry-be/description/project.md)。业务背景用于理解产品方向，不直接作为页面、菜单或接口已经存在的依据。

## 2. 当前范围与实现状态

| 项目 | 当前状态与边界 |
| --- | --- |
| 前端基础 | 使用 Vue 3、Vue Router 4、Vite 和 JavaScript ES Modules，页面已替换为注册中心骨架。 |
| 整体布局与视觉 | 已沿用 `contract-service-fe` 的分子背景、圆角半透明外框、顶部栏及入场过渡，并支持窄屏适配。 |
| 注册中心内部布局 | 数据中心采用左右布局，左侧包含平台同步、平台选择和筛选条件，右侧为文件列表，不再展示对话区或可调节分隔条；具体功能逐块设计，审核广场提供三栏布局、审核类型切换及正式入库及删除待审列表、原件预览与审核提交；人员管理暂不实现内容。 |
| 后端联动 | 已接入人员登录、平台与同步计划、正式目录及原件接口，配置本地 Vite 代理与生产 Nginx 转发；接口以注册中心后端的实际契约为准。 |
| 登录与账户栏 | 已实现真实密钥登录、后端账户名称、免登码会话、审核记录入口与退出。 |
| 审核记录 | 已接入本人入库审核及关联的删除审核历史，提供列表及详情；入库及删除审核决定已在审核广场接入，消息服务未接入。 |

登录页与注册中心采用独立路由，未登录访问注册中心会转至登录页，通过后端人员认证后，等待首屏数据、图标和渲染就绪再进入注册中心；同一标签页刷新可恢复会话凭据。顶部显示“注册中心”品牌、数据中心／审核广场／人员管理三个导航选项、后端返回的账户名称、审核记录与退出入口，数据中心左侧展示平台及条件筛选、右侧展示文件列表，平台列表与后端同步计划已接入；审核广场已完成三栏布局及正式入库及删除申请列表、详情及必填备注审核提交，人员管理目前为空白页面。页面地址与守卫见[页面路由](platform/routing.md)，登录边界见[登录与鉴权](platform/authentication.md)。审核广场布局见[审核广场三栏布局](features/review-square.md)，本人历史见[我的审核记录](features/review-history.md)。数据中心布局边界见[注册中心导航与数据中心](features/workspace.md)，后续业务面板、审核列表与智能体接口按明确需求实现。

## 3. 整体布局与风格参考

以同级知识沉淀体系中的 `contract-service-fe` 为视觉与布局参考。参考依据为其 [`src/App.vue`](../../../现象合同智能管理平台/contract-service-fe/src/App.vue) 和 [`src/style.css`](../../../现象合同智能管理平台/contract-service-fe/src/style.css)。

- **页面外框：** 全屏页面承载居中的注册中心容器，保留四周留白，容器采用大圆角、细边框和柔和阴影。
- **视觉层次：** 沿用浅色半透明表面、轻量渐变与深色文字的表达方式，保持背景、外框和顶部区域的层次。
- **顶部结构：** 参照左侧品牌、中部导航、右侧人员信息与操作入口的布局。顶部品牌使用“注册中心”；导航包含数据中心、审核广场和人员管理，右侧保留账户、审核记录与退出入口。
- **基础交互：** 字体、间距、按钮、选中态和过渡保持参考项目的一致性，同时兼顾键盘焦点、窄屏适配和减少动画偏好。

参考项目用于指导整体表现。合同库、合同处理、合同关系网等菜单、业务组件、状态模型和接口不属于本项目默认范围；不因参考项目已有某项能力而自动移植。

数据中心已移除左侧对话区和可调节分隔条，按已确认需求采用左侧筛选栏和右侧文件列表，具体功能逐块设计，平台概览采用一个平台对应一个文件夹实体，筛选条件包含入库日期、通行证前缀及文件名、摘要、申请人、审核人文本条件，与平台选择取交集；文本提示实时更新，失焦后应用筛选，支持统一重置；结果区域已接入正式目录与原件，支持 PDF、音频和视频预览、摘要与临时缓存；列表按入库时间降序、按年月分组，保留筛选变化的退出、入场与补位动画。

## 4. 后端联动边界

接口以[后端 API 参考](../../registry-be/description/api/readme.md)、对应专题及实际 OpenAPI 为依据，不从后端数据库或内部工作流推断浏览器端接口。

- 人员登录的请求、响应和错误语义见[人员登录 API](../../registry-be/description/api/auth.md)。前端会话存储、失效处理和退出交互应在接入时明确设计。
- 后端人员认证与服务器间的中间件平台会话是独立机制，前端不持有平台密钥或管理中间件会话。
- 人工审核、删除审核及智能体页面必须在需求与对外接口明确后实施，不预设地址、字段、权限或业务流程。
- 本地开发端口为 `23080`，生产域名为 `pheno.szkl.com`；页面与 API 采用同源转发，配置与上线边界见[环境与部署](platform/deployment.md)。
- 请求应明确呈现加载、成功、空结果和失败状态，认证失效时给出可恢复的交互，不用模拟成功掩盖接口缺失或调用失败。
- 不在代码、文档或构建产物中写入真实人员密钥、免登码及服务凭据。

## 5. 开发与质量原则

1. **事实优先：** 依据当前代码、有效配置、明确需求和可复现结果开展开发，区分现有能力、开发要求与待确认内容。
2. **职责清晰：** 页面表现、业务状态与数据访问保持清晰边界，不把后端职责转移到浏览器。
3. **适度抽象：** 只为实际重复或复杂度建立公共能力，不提前引入业务框架、状态库或参考项目的全部依赖。
4. **改动聚焦：** 以最小完整改动满足已确认需求，数据中心按确认后的设计逐块实现。
5. **失败可见：** 异常信息帮助用户恢复与开发者定位，同时避免暴露敏感信息。
6. **可验证性：** 文档检查链接与事实一致性；页面改动执行构建和相应交互验证；接口接入验证真实请求与主要失败路径。
7. **文档同步：** 行为、接口、配置与运行方式形成稳定事实后，更新相应专题及文档导航。
